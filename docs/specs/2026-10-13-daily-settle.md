## 5. Idempotency and retries

- **Every decision comes from the chain at one pinned block** (`resolve_markets.chain_snapshot`, `resolve_markets.py:231-235`) plus the committed files. Nothing comes from a previous run's state. Rerunning any step is a no-op once it has succeeded:
  - publish skips readings already on chain (`publish.py:390-439`)
  - finalize handles "already finalized" as an expected outcome (`finalize.py:327-330`)
  - resolve skips settled markets and markets someone else resolved first (`resolve_markets.py:396-401`)
- **"Never re-fetch a day that's already on chain"** is enforced at three levels:
  1. The step 3 gate. A day being on chain is never the reason for a fetch.
  2. The §8 guard. A metric file for a day with a reading on chain is never written, whichever machine runs the fetch.
  3. Raw re-reads of the three most recent days are already harmless: changed bytes go to `data/raw/superseded/` (`fetch_ercot.py:360-379`). §8 also has an optional stricter version that skips those re-reads.
- **Stop words: never retried, always alert and stop.** These all mean "a person must look":
  - `may still be in flight` (`publish.py:547-549`)
  - `VALUE MISMATCH`
  - `differs from immutable`
  - `Resolved event says`
  - any `CORRECTION` (an existing on-chain value would be replaced; in `--yes` mode this becomes an error, see §9A)
- **Every other non-zero exit from the RPC-based steps** (2, 4, 6, 7, 9) is retried once after 120 seconds. Those scripts already re-read the chain and avoid nonces below the confirmed count (`publish.py:230-241`).
- **Git:** before each push, `git pull --ff-only`. If a person pushed in the meantime and that fails, alert. The next run starts from a fresh pull.
- **Overlap:** the lock in step 0, or the GitHub `concurrency` group.

## 7. Alerting

1. **Alert when the job doesn't run** (this catches "nothing ran for a week"). Use one healthchecks.io check (free plan) with a cron schedule of `20 0 * * *` UTC, a 4-hour grace period, and its built-in Telegram and email integrations. The job sends:
   - `$HC_PING_URL/start` when it begins
   - `$HC_PING_URL` on success
   - `$HC_PING_URL/fail` on failure, with the last 60 log lines as the body

   "Success" means `settle_due.py --check` passed, not just that the script exited 0.
2. **Step failure.** A `trap … ERR` sends a fail ping and a Telegram message with the step name, exit code, the dayKeys involved, and the dry-run command a person should run next.
3. **Market-level checks** (`settle_due.py --check`, exit 3), any of which is a failure even when every step "worked":
   - **overdue:** closed more than 12 hours ago and not resolved
   - **cancel risk:** unresolved within 48 hours of `cancel()` opening
   - **unsettleable:** a market on a daylight-saving changeover day
   - **file drift:** a committed metric file's sourceHash differs from the chain (the 9 Oct symptom)
   - **out of range:** a published value below −$50 or above $1,000/MWh. Finalizing is held until a person decides.
   - **ladder running out:** no market day after tomorrow
   - **low gas:** reporter or settler below 0.005 OKB (balances read as in `state_report.py:250-255`)
4. **The dispute window keeps a person in the loop.** After publishing, Telegram receives: "Published 15 Oct: $31.20/MWh. Finalizes at 01:31 UTC." It also says how to stop it:
   - GitHub: `gh variable set SETTLE_HOLD --body 1` and cancel the run
   - Mac: `touch ~/.gridflex-settle-hold`

   The job checks the hold again right before finalizing.
5. **GitHub's own email** on failed scheduled runs, as a backup.

## 8. The guard: a fetch never rewrites a day that has a reading on chain

**Rule:** before any GridStatus request, read GridOracle for every publishable metric and day in the window. Merge the result with the ledger (the chain wins). Never write a file for a day found there, whether or not the file exists. If the oracle can't be read, stop before fetching or writing anything. There is no bypass flag.


**After `fetch_ercot.py:784`**: new function:
```python
def onchain_readings(metric_ids, days):
    """{"<metricId>:<dayKey>": chain reading} for every (metric, day) GridOracle
    already holds, read from the oracle itself rather than from the ledger.

    The ledger only lists what the reporter's machine has committed and this
    checkout has pulled. On 12 Oct the 9 Oct reading had been on chain for
    four hours when a refresh here, without that ledger row, rewrote its file
    with a new sourceHash and the site showed it unverified. Ledger rows
    recovered from chain carry no txHash, so published_readings() misses
    those too.

    Only metrics publish.py can submit are asked about (the fuel mix never
    goes on chain). Fails closed: a run that can't read the oracle stops
    before it fetches or writes anything, rather than assume nothing is
    published.
    """
    # Imported here, like gridstatusio in get_client(): web3 is needed only by
    # a run that writes metric files, not by the tests or the feed build.
    import publish

    wanted = [m for m in metric_ids if m in publish.EXPECTED_METRICS]
    if not wanted or not days:
        return {}
    try:
        _, oracle = publish.load_deployment()
        w3 = publish.make_web3(os.environ.get("XLAYER_RPC_URL", publish.DEFAULT_RPC_URL))
        chain_id = w3.eth.chain_id
        if chain_id != publish.EXPECTED_CHAIN_ID:
            raise SystemExit(f"Wrong chain: got {chain_id}, expected "
                             f"{publish.EXPECTED_CHAIN_ID}. Nothing was fetched or written.")
        contract = publish.load_contract(w3, oracle)
        found = {}
        for metric_id in wanted:
            for day in days:
                probe = publish.MetricReading(
                    path=Path("<fetch>"), metric_id=metric_id, day_key=day_key(day),
                    market_day_start_utc=0, market_day_end_utc=0,
                    value=0, source_hash="00" * 32)
                current = publish.chain_reading(contract, probe)
                time.sleep(ORACLE_READ_SLEEP)
                if current is not None:
                    found[probe.ledger_key] = current
        return found
    except SystemExit:
        raise
    except Exception as exc:
        raise SystemExit(
            "Could not read GridOracle to see which days are already published "
            f"({type(exc).__name__}). Nothing was fetched or written; run again "
            "when the X Layer RPC answers.")
```
