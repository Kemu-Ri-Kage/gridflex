# Changes, 23 September 2026

What this revision adds, and why. Nothing deployed changes: no contract, no
ABI, no address, no web component. Every existing test still passes and the
default behaviour of every existing script is unchanged.

## New

- `docs/OPS-RUNBOOK.md`. The dated calendar from today to the finale: the
  90-minute publish, finalize, resolve, redeem cycle for each live market
  (25 Sep, 29 Sep, 1 Oct evenings UTC), the markets to create for
  7 October, and today's two open items: publishing the full price history
  (the site says "3 of 376 days published onchain") and a full cycle with a
  trade and a `redeem()` in it, which has not happened on the chain yet.
- `verify_reading.py` and `tests/test_verify_reading.py`. Independent check
  of one oracle reading: chain against committed file, committed hash
  against raw files when present, and with `--fetch` a recompute of the
  price from GridStatus using the pipeline's own functions. This is the
  check anyone can run without our `data/raw/`.
- `claim_liquidity.py` and `tests/test_claim_liquidity.py`. Returns the
  seeded 10,000 mUSDT of a settled market to its provider. No script called
  `claimLiquidity()` before.
- `contracts/scripts/verify_contracts.sh`. Source verification of every
  deployed contract on OKLink. The address pages currently show bytecode.
- `.github/workflows/check.yml`. Runs `scripts/check_all.sh` on every push.

## Changed

- `fetch_ercot.py`: new `--tomorrow` flag (and `fetch_window(...,
  include_tomorrow=True)`). Without it, the day a market settles on is only
  read after 00:00 UTC, six and a half hours after the market closes.
  Default unchanged; `refresh_budget.py` and the tests are unaffected.
- `refresh_data.sh`: passes `--tomorrow` through.
- `scripts/check_all.sh`: byte-compiles the operator scripts too.
- `README.md`: test counts (503 after this revision, not 431), the price index line (one day is
  on the oracle, not the series), a one-transaction buy and a second
  reporter in "What's next", links to the runbook and `verify_reading.py`.
- `docs/technical-reference.md`, `docs/HANDOFF.md`, `shared/deployment.md`:
  the new scripts and the state of the lifecycle.
- `shared/submission-answers.md`: "anyone can recompute it" now says what
  is true, that anyone can recompute the number from public prices; the
  hash itself needs the raw files.

## Second revision, same day

- `refresh_data.sh`: the fetch and budget command lines are built from
  argument lists that start non-empty, so they expand the same way under
  `set -u` on Bash 3.2 (macOS) as on Bash 5. An empty array expansion
  there is an "unbound variable" error, which is what stopped the fetch
  step and failed three refresh tests on macOS. `--tomorrow` now reaches
  `refresh_budget.py` as well as `fetch_ercot.py`. Tests cover the default
  and `--tomorrow` command lines, that the fetch is never skipped, and that
  the request and row totals still include it.
- `refresh_budget.py --tomorrow`: budgets the extra day
  (`fetch_window(..., include_tomorrow=True)`), so the allowance guard
  never plans a smaller operation than the fetch that follows. Tests: the
  default budget is unchanged, the tomorrow budget is one more day of
  rows, and that day can be what tips a refusal.
- Request guards on direct runs, restored and reconciled with the current
  cache, `refresh_budget.py` and `--tomorrow`: `fetch_ercot.py --plan`
  (no API call), `--usage` (one usage request), `--max-requests` with a
  default of 10 that stops a run before its first request; the same three
  on `build_candles.py`. The planner (`plan_fetch`, `plan_reads`,
  `ROWS_PER_DAY`) lives in `fetch_ercot.py` and `refresh_budget.py` plans
  with it, so the two can't drift. `tests/test_request_budget.py` covers
  all of it. One existing candle test passes `--max-requests 50` because
  it plans against an empty cache.
- Finale date: the OKX Builder Kit puts the Singapore finale on
  **7 October 2026**, and no time of day has been given in writing. The
  runbook, handoff, `shared/demo-markets.md` and this file say 7 October,
  the claimed session window is gone, and the plan now explains that the
  `20261007` market resolves the evening before the presentation while
  `20261008` and `20261009` stay open through the whole of 7 October in
  Singapore.
