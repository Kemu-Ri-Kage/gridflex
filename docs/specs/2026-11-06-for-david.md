1. **Keys:**

     Give it about 0.05 test OKB.
   - Settler: `cast wallet new ~/.foundry/keystores gridflex-settler`.
     Give it 0.05 test OKB; mUSDT is free to mint.
   - Guardian: a wallet one of us controls, separate from both.
   - Owner: the existing deployer `0x27Aad…`.
2. **Deploy:**
   `forge script script/DeployOracleV2.s.sol:DeployOracleV2 --rpc-url xlayer_testnet --account gridflex-deployer --sender 0x27Aad02480f1DC01ebCb53fd7321a4629BCbe902 --broadcast`
   It needs the `OWNER_`, `REPORTER_`, `GUARDIAN_` and `DEPLOYER_ADDRESS`
   variables (see the doc).
3. **Switch over:** run `python scripts/switch_oracle.py --oracle <v2> --deploy-tx <tx>`
   (a dry run), then again with `--write`. Then run
   `python build_feed_data.py`, add `"settler": "<address>"` to
   `shared/addresses.json`, and merge it by pull request.
4. **Secrets:** add `REPORTER_KEYSTORE_JSON`/`_PASSWORD` and
   `SETTLER_KEYSTORE_JSON`/`_PASSWORD` to the `settle` Environment.
5. **Two nights** with `SETTLE_LIVE=yes` but no `SETTLE_CHAIN`. Compare the
   chain plan it prints (and the Telegram "due on chain" messages) with what
   is really due.
6. `gh variable set SETTLE_CHAIN --body yes`.

To stop at any point: `gh workflow disable daily-settle`, or
`gh variable delete SETTLE_LIVE`. A bad value: the guardian pauses and
voids (the drill in `shared/oracle-v2.md`).
